# PRD — P3 扫码出库 SaaS

> 第 3 个 SaaS 标品的完整 PRD + UI 设计。
>
> **战略定位**：钢贸最高频的"必经之路"——仓管每天 30+ 次。是平台留住用户最核心的功能。也是数据中台真实成交数据的最大入口。

---

## 一、产品概述

### 1.1 一句话
> 把钢贸现场的"装车-过磅-开单-签收"从"手写 5 张单 + 错率 15%"变成"扫码 5 步 + 0 错率 + 全程留痕"。

### 1.2 核心价值
- **效率**：单笔出库 5 分钟变 1 分钟
- **错率**：从 15% 降到 < 1%
- **追溯**：每一捆/每一支可追溯到客户/炉号/操作人
- **数据**：真实成交数据进入数据中台
- **金融**：M7+ 出库即触发保理放款

### 1.3 业务目标（M3）

| 指标 | 目标 |
|---|---|
| 试点仓库 | 5 家 |
| 月扫码出库单 | ≥ 5,000 单 |
| 错率 | < 1% |
| 单笔耗时 | < 1 min |
| 仓管满意度 | ≥ 85% |

## 四、核心功能详细设计

### 4.1 F3-001 智能推荐捆号（核心）

#### 业务流程
```
[系统接收提货单]
    └─ 输入参数：客户、规格、数量、客户偏好（指定钢厂/炉号？）
        └─ 智能匹配算法：
            1. 优先客户指定（钢厂/炉号）
            2. 先进先出（FIFO）
            3. 同垛位优先（减少调度）
            4. 满捆优先（减少散捆）
        └─ 推荐到具体捆号 + 垛位
            └─ 仓管在 PAD 看到："请到 A 区 03 垛位 取 5 捆"
```

#### 关键算法
```
推荐评分 = 
  客户偏好匹配 × 0.5 +  # 客户指定钢厂/炉号
  库龄匹配 × 0.2 +       # 先进先出
  位置便利 × 0.2 +       # 同垛位优先
  捆完整 × 0.1           # 满捆优先

输出 Top N 捆号 + 推荐理由
```

#### 异常处理
- 仓库无该规格 → 提示业务员（联动其他仓库 / 紧急采购）
- 数量不足 → 部分推荐 + 标"待补"
- 客户指定的炉号没货 → 提示"该炉号无货，是否接受替代？"

### 4.2 F3-002 扫码装车

#### 业务流程
```
仓管在 PAD 看到推荐捆号
    └─ 仓管去现场, 找到捆号
        └─ 扫码（每捆一次）
            └─ 系统校验: 是不是推荐的那捆?
                └─ 是 → 标记"已扫描"，显示进度
                └─ 不是 → 弹窗"该捆不在推荐列表，是否替代?"
                    └─ 替代 → 记录原因
                    └─ 取消 → 重新选
        └─ 装车计数 = 完成数 → 进入"过磅"
```

#### 强校验（关键）
- **不扫码不允许出库**（系统拒绝下一步）
- 扫码后捆号绑定到该出库单
- 数据中台收到扫码事件
- 异常实时推送给老板

### 4.3 F3-003 磅秤直连 + 自动过磅

#### 硬件接入
- 协议：RS485 / 串口 / 网口（支持主流磅秤）
- 设备：耀华 / 上海大华 / 梅特勒等品牌
- 网关：本地装一个边缘网关（小盒子）连磅秤

#### 业务流程
```
[车上磅] → 磅秤显示毛重
    └─ 系统自动读取（实时 5s 更新）
    └─ 自动拍照 4 张：车头 / 车尾 / 磅显屏 / 装载货物
    └─ 货卸下后, 车再次上磅 → 皮重
    └─ 净重 = 毛重 - 皮重
    └─ 系统校验：净重 ≈ 理计重量 (±0.3%)
        └─ 通过 → 进入打印
        └─ 异常 → 报警 (装多/少/规格错)
```

#### 异常告警
- 偏差超 ±0.3% → 红字弹窗 + 拒绝出库 + 通知主管
- 偏差超 ±1% → 通知老板
- 多次校验失败 → 锁定该出库单

### 4.5 F3-005 司机 APP

#### 接单
- 业务员/仓管派单 → 司机推送
- 司机在 APP 看：起点/终点/货品/重量/价格
- 司机点"接单"

#### 装车
- 到仓库后扫码"开始装车"
- 装车完成扫码"装车完成" + 拍 4 张照
- 自动同步出库单

#### 运输
- 运输中 GPS 实时共享给客户/平台
- 异常停留 > 30 min → 推送提醒

#### 签收
- 到达后扫描收货端二维码
- 客户在 H5 上电子签字
- 司机拍 2 张到货照
- 完成

### 4.8 F3-008 库存差异溯源

```
[仓管月底盘点发现]
  Φ16 螺纹账面 312 吨, 实际 298 吨, 差 14 吨

[点"差异溯源"]
    └─ 系统自动列出最近一次盘准后的所有进出库流水
        └─ 按操作人 / 时间 / 扫码记录
        └─ 视频快照
    └─ AI 自动分析: 可能原因 Top 3
        - 90% 装多（4 月 5 日某单装多 1 捆）
        - 5% 系统录入错误
        - 5% 实际损耗
    └─ 一键定位到具体出库单
    └─ 联系客户核对
```

### 4.9 F3-009 业务员异常行为预警

```
触发条件:
  - 业务员开出的出库单, 净重比理计偏差 > 0.5%
  - 业务员客户集中度异常 (Top 1 客户占 50%+)
  - 业务员出库价低于平台均价 3%
  - 业务员开出的出库单后, 客户突然不再下单

→ 系统自动推送给老板
→ 数据进入业务员风控档案
```

## 六、数据模型

```
DeliveryOrder (出库单)
  - id / contract_id / client_id / tenant_id
  - sku_list[] / expected_weight
  - assigned_warehouse_id / status / created_by

DeliveryItem (每捆/每垛)
  - id / order_id
  - bundle_code / sku_id / weight / heat_no
  - location_id / scanned_at / scanned_by

ScaleReading (磅秤记录)
  - id / order_id / vehicle_no
  - gross_weight / tare_weight / net_weight
  - photos[] / measurer_id / scale_id

QualityCertificate (质保书)
  - id / order_id / pdf_url
  - bundle_codes[] / heat_nos[]
  - chemical_data / mechanical_data

DriverApp (司机)
  - driver_id / vehicle_no
  - current_order_id / gps_locations[]
  - load_photos / signature

ClientReceipt (客户签收)
  - order_id / signed_at / signature
  - dispute_type / dispute_evidence

DeliveryAnomaly (异常)
  - order_id / type / severity
  - resolved_at / resolved_by

InventoryDiff (库存差异)
  - tenant_id / warehouse_id / sku_id
  - period / book_qty / actual_qty
  - diff / trace_data
```
