# 首批 5 家种子客户内测计划

> 本文是 24 / 28-33 号文档的执行细节。MVP W4-W8 阶段，选 5 家种子客户做深度内测，验证产品价值并形成案例。
>
> 适用读者：CEO / CCO 客户成功 / 销售 / 产品 / 客户成功经理。
>
> **核心目标**：
> - 验证产品价值是否真的解决客户痛点
> - 形成 5 个高质量案例，作为后续推广的"种子证据"
> - 让 5 家种子客户成为"超级用户"，自发推荐
> - 在真实场景中暴露产品 bug，快速迭代

---

## 一、为什么需要"种子客户内测"

### 1.1 痛点

| 不做内测的风险 |
|---|
| 产品上线后大面积 bug，损害品牌 |
| 客户发现"这不是我想要的"，流失严重 |
| 没有真实案例，销售无法说服新客户 |
| 数据不真实，运营优化无方向 |

### 1.2 内测的 4 大价值

1. **真实场景验证**：办公室验证 ≠ 客户现场验证
2. **快速试错**：5 家试错成本远低于 50 家
3. **案例资产**：5 个高质量案例 = 后续 1000 家的"信任前置"
4. **超级用户**：种子客户 → KOL → 自带流量

## 二、5 家种子客户筛选标准

### 2.1 评分维度

```
理想种子客户应满足:

1. 已是 ERP 老客户 (3 年+, 信任基础好)
2. 中型规模 (5-30 万吨, 痛点最痛)
3. 老板亲自参与决策 (执行力强)
4. 业务员 / 财务 / 仓管 团队配合度高
5. 地理位置便于现场支持 (上海/华东优先)
6. 行业有一定影响力 (后续案例宣传)
7. 愿意接受短期 bug 和不完善
8. 同意提供数据贡献授权
9. 可以暴露内测过程 (案例宣传)
```

### 2.2 评分卡

```
候选客户评分 (满分 100):
  - ERP 老客户年限   (10 分)
  - 规模匹配         (15 分)
  - 老板配合度       (20 分)
  - 团队执行力       (15 分)
  - 地理便利         (10 分)
  - 行业影响力       (10 分)
  - 接受不完善       (10 分)
  - 数据授权         (5 分)
  - 案例宣传授权     (5 分)
```

### 2.3 5 家候选画像（建议）

```
候选 1: 上海 XX 钢贸 (中型, 螺纹+板材)
  - ERP 老客户 5 年
  - 年销 12 万吨
  - 老板亲自管业务
  - 上海, 便于支持
  - 行业小有影响

候选 2: 杭州 XX 钢贸 (中型, 管材为主)
  - ERP 老客户 4 年
  - 年销 8 万吨
  - 老板娘负责财务+IT
  - 杭州, 便于支持
  - 数字化意愿强

候选 3: 苏州 XX 钢贸 (中型, 多品类)
  - ERP 老客户 3 年
  - 年销 15 万吨
  - 团队年轻 (90 后老板)
  - 接受新技术
  - 已经在折腾各种 SaaS

候选 4: 南京 XX 钢贸 (中型, 加工配送)
  - ERP 老客户 4 年
  - 年销 20 万吨 + 加工
  - 痛点最复杂 (适合压力测试)
  - 老板务实

候选 5: 上海 XX 钢贸 (调货公司)
  - ERP 老客户 3 年
  - 年销 5 万吨 (调货为主)
  - 业务员 8 人
  - 适合验证 AI 报价

注: 实际选择需基于 2000 家 ERP 客户名单评估
```

## 三、内测计划（4 周节奏）

### 3.1 阶段一：W4 招募与启动（M1 末）

#### Day 1：CEO 个人邀请
```
CEO 亲自打电话给 5 家老板:
  - 表明诚意: "您是我们最重要的老客户"
  - 说明价值: "免费深度服务, 第一批用上未来钢贸的工具"
  - 强调互惠: 
    - 客户得到: 6 个月免费会员 (¥ 19,800 价值) + 1v1 客户成功支持 + 行业大会嘉宾资格
    - 平台得到: 真实场景反馈 + 案例授权
  - 时间安排: 1 小时面谈
```

#### Day 2-7：现场拜访
```
CEO + 产品总监 + 客户成功经理 三人组:
  - 上门拜访 5 家
  - 1.5 小时深度访谈 (按 06 号文档访谈提纲)
  - 现场看仓库 / 业务流程
  - 拍照 / 录像 (征得同意)
  - 签订内测协议
  - 收集团队联系方式 (老板/业务员/财务/仓管)
```

#### 内测协议要点
```
协议内容:
  1. 内测期: 8 周 (W5-W12)
  2. 客户权利:
     - 6 个月免费企业版
     - 优先客户成功支持 (4 小时响应)
     - 创始人月度闭门会
     - 案例宣传可优先看稿
  3. 客户义务:
     - 至少 5 个核心员工注册使用
     - 每周 1 次产品反馈
     - 同意脱敏数据用于产品优化
     - 同意内测过程作为案例宣传
  4. 风险揭示:
     - 内测产品可能存在 bug
     - 不可逆操作有保护机制
     - 重大问题平台兜底
```

### 3.2 阶段二：W5-W6 上线 P1 + P2（小步快跑）

#### W5：P1 钢价行情上线
```
Day 1 (周一):
  - 客户成功上门, 协助 5 家注册
  - 老板 / 业务员 / 财务 / 仓管 都注册
  - 现场演示如何看早报

Day 2-5:
  - 早 7:00 开始正式推送
  - 客户成功每天 1 次电话回访
  - 收集"早报内容是否有用"反馈
  - 优化 AI 解读

周末:
  - 周报: 5 家激活率 / 阅读率 / 反馈
```

#### W6：P2 电子对账单上线
```
Day 1 (周一):
  - 客户成功上门, 培训财务
  - 协助生成第一张对账单
  - 帮助财务把客户名单导入

Day 2-5:
  - 每天 1-2 张对账单测试发送
  - 跟踪客户接收方扫码情况
  - 测试异议流程
  - 测试病毒位转化

周末:
  - 复盘: 5 家共发了多少张对账单
  - 客户接收方注册转化率多少
  - 病毒位文案 A/B 测试
```

### 3.3 阶段三：W7-W8 上线 P3 + P4（核心价值验证）

#### W7：P3 扫码出库 (重头戏)
```
Day 1-2:
  - 客户成功 + 研发 上门部署磅秤连接
  - 仓管现场培训
  - 第一笔扫码出库 (CEO 亲自见证)

Day 3-5:
  - 仓管每天扫码 5+ 单
  - 现场观察问题
  - 紧急 bug 修复

周末:
  - 复盘: 5 家共扫码多少单
  - 错率多少
  - 仓管满意度
```

#### W8：P4 AI 报价
```
Day 1:
  - 业务员培训
  - 演示 AI 4 数字
  
Day 2-5:
  - 业务员每天用 5+ 次
  - 收集"AI 建议价是否合理"反馈
  - 老板审批流测试
  - 客户主权机制验证

周末:
  - 复盘: AI 推荐 vs 业务员实际报价偏差
  - 老板审批响应时间
```

### 3.4 阶段四：W9-W10 P5 + P6 + 复盘

#### W9-W10：P5 资金大盘 + P6 社区
```
P5 资金大盘:
  - 老板每天打开 N 次
  - 资金告警是否有效
  - 电子合同试用

P6 社区:
  - 5 家老板加入早期社区
  - 创始人亲自互动
  - 测试老赖榜（M5 上线前）
```

#### W10 末：综合复盘
```
- 5 家客户深度访谈 (1.5 小时/家)
- 团队复盘会
- 产品迭代清单
```

## 四、客户成功 SOP（每家 1 个专属经理）

### 4.1 每周节奏

```
周一 09:00:
  - 客户成功每周计划
  - 同步本周新功能 / bug 修复

周一 14:00-17:00:
  - 5 家客户分别 1v1 (每家 30 min)
    - 上周问题
    - 本周计划
    - 收集反馈

周二-周四:
  - 远程支持 (企微 / 电话)
  - 上门 (有重大问题时)

周五 14:00-16:00:
  - 周复盘
  - 周报发出 (CEO + 产品 + 全团队)
```

### 4.2 响应 SLA

```
P0 紧急 (业务停摆):
  - 30 min 响应
  - 4 小时解决
  - CEO + CTO 介入

P1 重要 (核心功能):
  - 2 小时响应
  - 24 小时解决

P2 一般:
  - 工作日 8 小时响应
  - 5 个工作日解决

P3 建议:
  - 工作日响应
  - 月度迭代
```

### 4.3 客户反馈收集

```
每家客户专属"内测反馈群" (企微):
  - 客户老板 / 关键员工
  - 平台: CEO / 产品总监 / 客户成功 / CTO

每周固定时段问卷:
  - 本周用了哪些功能?
  - 满意度 1-10
  - 最痛的 1 个 bug
  - 最想要的 1 个新功能

反馈分类:
  - bug
  - 优化建议
  - 新需求
  - 表扬

反馈回应:
  - 每条 24 小时内回复
  - "已记录" / "已修复" / "本周做" / "归档"
```

## 五、关键 KPI 与里程碑

### 5.1 内测成功标准

```
W4 末 (招募阶段):
  ✅ 5 家客户签订内测协议
  ✅ 5 个客户成功经理到位

W6 末 (P1+P2 上线):
  ✅ 5 家激活率 ≥ 80%
  ✅ 月发对账单 ≥ 200 张
  ✅ 客户接收方扫码率 ≥ 70%
  ✅ 早报阅读率 ≥ 50%

W8 末 (P3+P4 上线):
  ✅ 5 家扫码出库 ≥ 100 单/家
  ✅ 出库错率 < 2%
  ✅ AI 报价使用 ≥ 50 次/家
  ✅ 业务员满意度 ≥ 4/5

W10 末 (P5+P6 上线):
  ✅ 5 家老板每周打开 ≥ 5 次
  ✅ 资金告警响应率 ≥ 60%
  ✅ 5 家全部签订正式服务合同

W12 末 (内测结束):
  ✅ 5 家全部成为正式客户
  ✅ 5 个完整案例视频拍摄完成
  ✅ 至少 3 家愿意"老带新"
  ✅ 整体 NPS ≥ 60
```

### 5.2 内测失败信号（提前预警）

```
W6 末警戒:
  ❌ 任 1 家激活率 < 50% → 客户成功上门救场
  
W8 末警戒:
  ❌ 任 1 家想退出内测 → CEO 亲自电话挽留
  ❌ 出库错率 > 5% → 紧急砍掉非核心功能
  
任何时候:
  ❌ 数据合规事故 → 立即停用 + 法务介入
  ❌ 客户业务受损 (因平台 bug) → 平台赔偿
```

## 六、案例资产产出

### 6.1 案例形式（每家产出 5 类）

```
1. 案例文章 (公众号深度长文 2000 字)
   - 客户老板访谈
   - 数字化前后对比
   - 数据 (省了多少时间 / 钱)

   - 客户老板出镜
   - 现场画面
   - 数字化前后对比
   - 用于视频号 / 抖音 / 销售

3. 案例 PPT (10 页)
   - 用于销售拜访新客户
   - 用于行业大会演讲

4. 案例数据 (Excel + 图表)
   - 客户量化收益
   - 用于融资材料

5. 案例 H5 海报
   - 朋友圈传播
   - 二维码引流
```

### 6.2 案例宣传节奏

```
W10 末:
  - 5 个案例文章上线公众号
  - 5 个案例视频上线视频号 / 抖音
  - 行业媒体 (钢联资讯 / 我的钢铁) 互推

W12 末:
  - 案例 PPT 完成
  - 行业大会 (M3 末筹备 / M4 举办)
  - 5 家老板作为嘉宾出席

后续每月:
  - 1-2 个新案例发布
```

## 七、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 招募失败 (5 家凑不齐) | 内测计划延期 | 候选名单准备 8-10 家, 有备份 |
| 客户中途退出 | 案例缺失 | 内测协议明确退出条款, 客户成功强力维护 |
| 重大 bug 事故 | 客户损失 | 内测期平台兜底赔偿 (预算 50 万) |
| 数据合规事故 | 业务停滞 | 法务前置审核, 客户授权完整 |
| 老板没时间用 | 数据失真 | 重点拉拢 1 个内部 KOL (业务员 / 财务) |
| 团队抵制 | 激活率低 | 老板亲自要求 + 客户成功上门 |

## 十一、最终结论

> **5 家种子客户内测是 MVP 阶段最重要的客户工作。**
>
> **目标不是"卖更多产品", 而是:**
> 1. **验证产品真的解决问题** (避免方向性错误)
> 2. **形成 5 个高质量案例** (后续推广的"种子证据")
> 3. **培养 5 个超级用户** (成为 KOL 自带流量)
>
> **关键原则**:
> - CEO 必须亲自参与 (前 2 周每天)
> - 客户成功 1v1 服务 (5 个专属经理)
> - 失败要快, 重大问题宁可推倒重来
> - 案例资产是后续 1000 家客户的"信任前置"
>
> **没有种子客户, 没有产品迭代; 没有案例资产, 没有规模化推广。**
