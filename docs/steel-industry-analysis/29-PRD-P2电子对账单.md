# PRD — P2 电子对账单 SaaS

> 第 2 个 SaaS 标品的完整 PRD + UI 设计。
>
> **战略定位**：病毒拉新核心引擎。每月发出 50w-100w 张对账单 = 50w-100w 次品牌曝光 = 平台最大获客通道。

---

## 一、产品概述

### 1.1 一句话
> 钢贸老板每月对账，从"Excel + 微信 5 天扯皮"到"H5 一键发出 + 客户在线确认"。

### 1.2 核心价值
- **财务效率**：月底对账从 5 天到 1 天
- **争议留痕**：所有发送/已读/确认/异议有记录
- **病毒拉新**：每张对账单底部带"免费试用"引导
- **数据沉淀**：客户付款行为数据进入数据中台

### 1.3 业务目标（M3）

| 指标 | 目标 |
|---|---|
| 月发对账单数 | ≥ 5w 张 |
| 对账单接收方扫码率 | ≥ 80% |
| 在线确认率 | ≥ 75% |
| 接收方注册转化率 | ≥ 8% |
| 异议自动派单闭环率 | ≥ 60% |

## 四、核心功能详细设计

### 4.1 F2-001 一键生成对账单

#### 业务流程
```
[财务点"对账中心" → "新建"]
    └─ 选客户范围（全部 / 分组 / 单选）
        └─ 选周期（月度 / 自定义）
            └─ 系统自动从 ERP / 出库 / 票据 / 收款各服务汇总
                └─ 生成草稿
                    └─ 财务可调整（增删行、修改备注）
                        └─ 进入"待发送"状态
```

#### 自动汇总规则
| 数据 | 来源 |
|---|---|
| 期初余额 | 上月末"已确认"对账单的期末余额 |
| 出库明细 | P3 扫码出库（按客户聚合） |
| 开票明细 | 财务系统（含蓝/红字） |
| 收款明细 | P5 资金大盘 |
| 承兑票 | P5 票据池 |
| 退货 | P3 退货事件 |
| 期末余额 | = 期初 + 出库 - 收款 - 票据 + 退货 |

#### 异常处理
- 数据不全：标"⚠️"提示财务核查
- 客户主数据缺失：跳到"补全客户档案"
- 计量方式冲突（理计 vs 过磅）：财务确认按哪个

### 4.2 F2-002 H5 对账单页面（核心）

#### 设计原则
- **极简**：一屏看完关键数据
- **专业**：印章 / Logo / 公司抬头
- **可信**：所有数据可点击查看明细
- **友好**：移动端优先，扫码即看

#### 页面结构（详见 5.2 UI 草图）

```
顶部
  - 公司 Logo + 名称
  - 对账周期 (如 2026-04-01 ~ 2026-04-30)

汇总卡片
  - 期初余额: ¥ XX 万
  - 本期出库: ¥ XX 万
  - 本期开票: ¥ XX 万
  - 本期收款: ¥ XX 万
  - 期末余额: ¥ XX 万

明细行（可折叠）
  - 出库明细
  - 开票明细
  - 收款明细
  - 票据明细
  - 退货明细

底部操作区
  [确认无误] [我有异议]

底部引导
  关注公众号 → 下载 PDF
  你也可以免费用 → 注册引导
```

### 4.3 F2-003 在线确认/异议

#### 确认流程
```
客户点 [确认无误]
  → 弹窗："请扫描下方二维码绑定您的微信，以便我们记录您的确认"
  → 客户授权 → 状态变更：已确认
  → 推送给财务：客户已确认
  → 关闭对账单
```

#### 异议流程
```
客户点 [我有异议]
  → 弹出表单：
      - 异议类型: ☐ 金额错 ☐ 数量错 ☐ 单价错 ☐ 收款未到 ☐ 其他
      - 异议明细: 选具体某行
      - 备注（必填）
  → 提交 → 状态变更：异议中
  → 推送给业务员（不是财务）+ 老板抄送
  → 业务员处理 → 修改对账单 → 重新发送 → 客户确认
```

### 4.5 F2-005 多渠道发送

| 渠道 | 适用 | 形式 |
|---|---|---|
| **微信** | 默认（最高优先级） | H5 链接发到微信 |
| **短信** | 备用 | 短信带短链 |
| **邮件** | 大客户 / 财务对账 | 邮件 + PDF 附件 |
| **企微** | 内部协同 | 企微消息 + H5 链接 |
| **小程序** | 已注册客户 | 小程序内部消息 |

#### 一键发送
```
[对账单草稿]
  → [选择发送方式] 多选
      ☑ 微信       客户手机号自动匹配微信
      ☐ 短信        
      ☐ 邮件        客户邮箱
  → 一键发送
  → 系统自动按选择渠道并发
  → 状态变更：已发送
  → 留痕：发送时间 / 渠道 / 链接 / 短信 ID 等
```

### 4.6 F2-006 异议派单

#### 自动派单规则
```
异议类型 → 派给谁
  - 金额错 / 单价错 / 数量错 → 业务员（该客户对接人）
  - 收款未到 → 财务
  - 其他 → 老板默认审批
```

#### 派单 SLA
- 24 小时内必须响应（系统自动催促）
- 72 小时未响应 → 升级到老板
- 7 天未关闭 → 升级到客户成功团队

### 4.7 F2-007 自动催收（付费版）

#### 催收规则
```
对账单状态 + 距发送天数 → 触发动作

- 已发送 + 3 天未读 → 系统自动短信提醒客户
- 已读 + 5 天未确认 → 业务员收到提醒
- 已确认 + 30 天未付款 → 系统催收短信
- 已确认 + 60 天未付款 → 业务员电话催收任务
- 已确认 + 90 天未付款 → 老板抄送 + 风险预警
```

### 4.8 F2-008 模板管理（付费版）

#### 可定制
- 公司 Logo
- 印章图片
- 抬头/落款
- 颜色主题
- 字体
- 联系方式
- 备注模板
- 列名（如把"金额"改成"含税金额"）

#### 模板预览
- 实时预览
- 多模板可保存
- 设置默认模板

### 4.9 F2-009 PDF 导出 + 电子签章（付费版）

#### PDF 生成
- 客户端在公众号回复"对账单 + 编号"获取
- 财务端可直接下载

#### 电子签章
- 接 e签宝 / 法大大 / 第三方签章
- 双方在 H5 完成签章
- 签章后 PDF 不可篡改
- 法律效力等同纸质

```
  - status / creator_id

Statement (单张对账单)
  - id / batch_id / tenant_id / client_id
  - opening_balance / closing_balance
  - total_outbound / total_invoiced / total_received / total_notes
  - share_token / status
  - sent_at / viewed_at / confirmed_at

StatementItem (明细)
  - statement_id / biz_type(出/开/收/票/退)
  - biz_doc_no / biz_date
  - sku_id / quantity / unit / amount / remark

StatementDispute (异议)
  - statement_id / item_ids[] / reason
  - status / replied_by / replied_at / reply

StatementShareLog (分享日志/病毒漏斗)
  - statement_id / share_channel
  - viewer_openid / viewer_device
  - viewed_at / converted_to_register / converted_user_id

DunningTask (催收)
  - statement_id / rule_id / triggered_at
  - action_type / action_result
```
