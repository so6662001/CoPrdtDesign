# 数据交易所对接技术方案

> 本文是 16 / 19 / 20 文档的技术配套，给出与上海/深圳/北京数据交易所对接的完整技术方案：从数据产品挂牌到交易闭环的端到端实施路径。
>
> 适用读者：CDO / CTO / 数据架构师 / 数据产品经理 / 数据交易合规专员。
>
> **本文是一份"可执行"技术方案**，包含：合作流程、产品设计、技术架构、合规要点、上线节奏、KPI。

## 一、为什么要对接数据交易所

### 1.1 战略意义

| 价值 | 说明 |
|---|---|
| **合规背书** | 在数据交易所挂牌 = 政府认可的合法数据产品 |
| **客户拓展渠道** | 交易所有自己的金融机构客户群 |
| **数据资产估值依据** | 挂牌 = 公允价值参考（用于入表） |
| **品牌信任** | "数据交易所挂牌产品"是销售背书 |
| **政策友好** | 与监管机构形成良性互动 |

### 1.2 中国主流数据交易所

| 交易所 | 成立 | 特点 | 我们的策略 |
|---|---|---|---|
| **上海数据交易所** | 2021 | 国家级、业务最成熟 | **首选**，作为旗舰挂牌 |
| **深圳数据交易所** | 2022 | 金融数据强、跨境资源 | **次选**，金融数据挂牌 |
| **北京国际大数据交易所** | 2021 | 政策资源、央企资源 | 与政策机构合作 |
| **贵阳大数据交易所** | 2014 | 老牌但近年式微 | 不优先 |
| **重庆/河南/西安等地数交所** | — | 区域性 | 区域产品试点 |

## 二、合作流程（端到端）

### 2.1 完整对接流程（约 3–6 个月）

```
Step 1: 资质准备（M0–M1）
  ├ 公司主体合规（营业执照 / 法人 / 数据服务备案）
  ├ 产品合规（数据来源 / 用户授权 / 脱敏方案）
  └ 申请会员（上海/深圳数据交易所）
        ↓
Step 2: 会员审核（M1–M2，约 30–60 天）
  ├ 提交资料：营业执照、法定代表人、业务说明、数据来源说明
  ├ 数据交易所审核（含监管口径核查）
  └ 通过后签订《数据交易所会员协议》
        ↓
Step 3: 数据产品申请挂牌（M2–M3）
  ├ 产品命名 + 数据范围 + 数据规格 + 定价
  ├ 数据合规审查（数据来源 / 脱敏 / 权益）
  ├ 数据质量评估（完整性 / 准确性 / 时效性）
  └ 上链/挂牌（公示期 7–14 天）
        ↓
Step 4: 技术对接（M3–M4）
  ├ API 接入交易所
  ├ 数据传输安全
  ├ 计费对接
  └ 联调测试
        ↓
Step 5: 正式上线（M4+）
  ├ 上线公告
  ├ 客户开发
  └ 持续运营
```

### 2.2 关键文件清单

| 阶段 | 必备文件 |
|---|---|
| **资质准备** | 营业执照、法人身份证、ICP 备案、等保 2 级证书、数据服务备案、用户协议、隐私政策、数据贡献授权条款 |
| **产品挂牌** | 产品说明书、数据规格书、数据来源证明、合规评估报告、定价方案、SLA |
| **技术对接** | API 接口文档、接入手册、数据传输方案、安全方案 |
| **运营** | 用户使用手册、客户成功 SOP、计费记录 |

### 3.2 产品规格示例（P1：CSP API）

```yaml
产品名称: 钢贸真实成交价指数 API（CSP API v1.0）
产品 ID: GLT-CSP-001
所属交易所: 上海数据交易所

数据规格:
  覆盖品种: 螺纹钢、线材、热卷板、冷轧板、镀锌板、中厚板、管材、型材
  覆盖区域: 全国、华东、华北、华南、西南、西北、东北
  数据频率: 实时（5 分钟更新）
  历史数据: 从 2026-01-01 起
  
数据字段（每条记录）:
  - sku_id: 品种规格 ID
  - region: 区域
  - timestamp: 时间戳
  - real_avg_price: 真实加权均价
  - transaction_volume: 成交量（吨）
  - transaction_count: 成交笔数
  - confidence_score: 置信度（0-1）
  - region_avg_price: 区域均价
  - mom_change: 环比变化
  - yoy_change: 同比变化

API 形式:
  - REST API: GET /api/v1/csp?sku=XXX&region=XXX&start=YYY&end=ZZZ
  - WebSocket: 订阅实时推送
  - 数据下载: 历史数据 Excel/Parquet
  
计费模式:
  - 订阅模式: 50 万/年（不限调用）
  - 按调用模式: 1,000 元/万次
  
SLA:
  - 可用性: 99.9%
  - 数据延迟: ≤ 5 分钟
  - 响应时间: P95 ≤ 200ms
  
合规:
  - 数据来源: 平台 2,000+ 钢贸商授权数据
  - 脱敏: 单家企业不可识别（K-匿名性 K=10）
  - 用途限制: 仅限客户内部使用、不得转售
```

### 4.2 关键技术栈

| 层 | 技术选型 | 说明 |
|---|---|---|
| **数据采集** | Flink CDC / Kafka | 实时同步 |
| **数据湖** | Iceberg + S3 / OSS | 分层存储 |
| **流计算** | Flink | 实时指数计算 |
| **批量计算** | Spark | 离线分析 |
| **OLAP** | ClickHouse / Doris | 即席查询 |
| **API 网关** | Apache APISIX / Kong | 鉴权+限流+计费 |
| **数据传输** | TLS 1.3 + 加密 | 安全 |
| **数据脱敏** | 自研脱敏中间件 + Privacera | K-匿名 / 差分隐私 |
| **审计日志** | ELK + 数据库 | 合规追溯 |
| **监控** | Prometheus + Grafana | 性能 + 可用性 |

### 4.3 与数据交易所对接的 API 规范

```yaml
对接接口 1: 产品元数据同步
  POST /sde-api/v1/products
  描述: 我方向交易所同步产品 metadata
  内容: 产品 ID、名称、定价、SLA、规格

对接接口 2: 客户授权同步
  POST /sde-api/v1/customer-auth
  描述: 客户在交易所购买后, 交易所通知我方激活客户访问
  内容: 客户 ID、产品 ID、授权周期、API Key

对接接口 3: 调用计量同步
  POST /sde-api/v1/usage-sync
  描述: 我方每日同步客户调用量给交易所(用于结算)
  内容: 客户 ID、产品 ID、调用次数、数据量

对接接口 4: 客户终止
  POST /sde-api/v1/customer-revoke
  描述: 客户结束订阅后, 交易所通知我方停用 API Key

对接接口 5: 合规审计
  GET /sde-api/v1/compliance-audit
  描述: 交易所定期审计我方数据使用情况
  内容: 查询范围、用户访问日志、合规报告
```

## 五、数据脱敏与合规设计（重点）

### 5.1 数据脱敏 SOP

```
原始数据 (来自 ERP/SaaS)
    ↓
[Step 1] 字段分级
  - L1 高敏: 企业名称、信用代码、法定代表人、联系方式
  - L2 中敏: 具体合同金额、价格、客户、库存细节
  - L3 低敏: 行业、地区、品种类别
    ↓
[Step 2] 脱敏处理
  - L1: 删除 / 哈希 + 不可逆
  - L2: 模糊化 / 区间映射 / 加噪
  - L3: 保留（用于聚合统计）
    ↓
[Step 3] 实体合并
  - 按统一信用代码合并同一企业的多笔交易
  - 按规格归类
  - 按时间窗口聚合
    ↓
[Step 4] K-匿名性验证
  - 任意 K 个企业的数据组合后不可被识别
  - 默认 K = 10（敏感产品 K = 50）
    ↓
[Step 5] 差分隐私（高敏感产品）
  - 添加噪声（拉普拉斯 / 高斯）
  - 保证个体不可推断
    ↓
入指数库（脱敏后）
```

### 5.2 不同产品的脱敏强度

| 产品 | K 值 | 差分隐私 | 共享层级 |
|---|---|---|---|
| CSP 价格指数 | K=10 | 否 | 公开 API |
| CSC 信用指数（按企业查） | 无脱敏（明确授权后） | 否 | 仅授权金融机构 |
| 钢厂提货月报 | K=20 | 否 | 公开 |
| 库存周转日报 | K=10 | 否 | 公开 |
| 资金压力季报 | K=50 + DP | 是 | 仅政府 |

### 5.3 数据使用审计

每次客户调用 API 都必须记录：

```json
{
  "timestamp": "2026-04-27T10:23:45Z",
  "customer_id": "CUS-12345",
  "product_id": "GLT-CSP-001",
  "endpoint": "/api/v1/csp",
  "request_params": {...},
  "response_size_bytes": 2048,
  "ip_address": "x.x.x.x",
  "user_agent": "...",
  "compliance_check": "PASS"
}
```

数据交易所有权随时审计这些日志。

## 九、风险与应对

### 9.1 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 挂牌审核未通过 | 延误 3–6 个月 | 提前完善合规材料 + 与数交所深度沟通 |
| 数据脱敏不达标 | 产品被强制下架 | 严格按 K-匿名 + DP 标准 |
| 客户违规使用数据 | 监管处罚 | 数据使用监控 + 客户协议约束 |
| 数据交易所规则变化 | 业务调整 | 定期跟踪监管动态 |
| 跨境数据出境 | 网信办处罚 | 严格按出境安全评估办法 |

### 9.2 风险应对预案

```
事件: 数据交易所要求下架某产品
响应:
  1. 1 小时内召集 CDO/CTO/法务/产品紧急会议
  2. 24 小时内回应数交所(认错或申辩)
  3. 48 小时内提交整改方案
  4. 1 周内完成整改
  5. 重新申请上架
```
