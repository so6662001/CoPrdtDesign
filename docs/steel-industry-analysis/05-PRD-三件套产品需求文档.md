# PRD — 三件套产品需求文档（电子对账单 + 钢贸征信 + 库存资源圈）

> 本 PRD 面向研发交付，覆盖三件套产品的：业务目标、用户角色、核心流程、数据模型、状态机、关键功能字段、API、合规设计、灰度与迭代节奏。
>
> 适用读者：产品经理、研发、UI/UX、测试、法务合规、数据安全。

---

## 0. 文档约定

- **优先级**：P0 = MVP 必上 / P1 = MVP 后第一波迭代 / P2 = 远期。
- **角色简写**：`OWNER`（钢贸老板）/ `SALES`（业务员）/ `FIN`（财务）/ `WAREHOUSE`（仓管）/ `CLIENT`（对账单/合同接收方）/ `BUYER`（资源圈采购方）/ `SELLER`（资源圈卖货方）/ `ADMIN`（平台管理员）。
- **术语**：
  - 「数据贡献者」= 通过 ERP / 对账单 / 合同 / 磅单工具，向平台脱敏贡献数据的企业。
  - 「征信主体」= 被查询的企业（钢贸的客户）。
  - 「征信报告」= 平台基于多方贡献数据 + 第三方数据生成的企业风险画像。

## 1. 产品 A — 电子对账单 SaaS（病毒拉新入口）

### 1.1 业务目标

| 目标 | 指标 |
|---|---|
| 拉新（首要） | 月发对账单 ≥ 50w 张，对账单接收方扫码注册转化率 ≥ 8% |
| 激活 | 现有 2000 家 ERP 客户激活率 ≥ 60% |
| 数据沉淀 | 收集"客户的客户"通讯录与往来流水，作为征信底座 |
| 体验闭环 | 对账确认率 ≥ 75%（客户在线点确认/异议） |

### 1.2 用户角色与权益

| 角色 | 权益 | 限制 |
|---|---|---|
| ERP 老客户（OWNER/FIN） | 一键导入 ERP 数据；模板美化；批量发对账单 | — |
| 免费注册新用户 | 手动录入或 Excel 导入；月发 ≤ 50 张 | 模板水印；高级模板锁定 |
| 付费用户（99/m，999/y） | 无限发；自定义模板/Logo/印章；导出 Excel；催收提醒 | — |
| 对账单接收方 CLIENT | 无需注册即可扫码查看；可在线"确认/异议"；可关注公众号保存 PDF | — |

### 1.3 核心流程

#### 1.3.1 主流程：从 ERP 一键发对账单

```
[OWNER/FIN 在 ERP 后台]
    └─ 点击"对账单中心"
        └─ 选择"对账周期"（月度/自定义）
            └─ 选择客户范围（全部/分组/单个）
                └─ 系统自动汇总：合同清单 + 出库单 + 发票 + 收款 + 票据 + 余额
                    └─ 生成对账单草稿（可预览/编辑）
                        └─ 选择发送方式：微信小程序/H5链接/短信/邮件
                            └─ 一键发送
                                └─ 状态变更：已发送
                                    └─ 客户扫码 → 状态变更：已查看
                                        └─ 客户点击 → 已确认 / 异议提交
                                            └─ 异议自动回流 SALES 跟进
```

#### 1.3.2 病毒裂变路径（关键设计）

```
对账单 H5 页面底部：
    ┌────────────────────────────────────────┐
    │ 本对账单由「钢链通」生成 · 免费试用 →    │
    │ ─────────────────────────────────────  │
    │ ✅ 对账单确认后，弹出引导：             │
    │   "想给你的客户也发这种对账单？        │
    │    扫码即免费注册，30 秒上手 →"        │
    └────────────────────────────────────────┘

转化漏斗目标：
- 对账单送达率 ≥ 95%
- 扫码打开率 ≥ 80%
- 在线确认率 ≥ 75%
- 注册转化率 ≥ 8%（关键 KPI）
- 注册→激活（发出第一张对账单）≥ 50%
```

### 1.5 状态机

```
StatementBatch:  draft ──发送──> sending ──全部送达──> sent ──手动归档──> closed

        └─ 对方提交异议──> disputed ──回复处理──> resolved ──对方再确认──> confirmed
```

### 1.7 合规与风控

- 用户协议明示：发对账单需告知接收方"本平台用于电子对账+免费工具体验"；
- 对账数据归发起方所有，平台仅做处理/存储；
- 接收方扫码后未注册时，仅展示对账单内容，不留任何隐私字段；
- 短信/邮件需走合规模板备案（避免被运营商拦截）。

## 2. 产品 B — 钢贸征信 / 客户风险共享平台（数据网络锁定）

### 2.1 业务目标

| 目标 | 指标 |
|---|---|
| 数据底座 | 12 个月内覆盖 ≥ 5w 个钢材买家主体 |
| 网络效应 | 月活查询 ≥ 5w 次；数据贡献者 ≥ 1w 家 |
| 变现 | 企业版年费用户 ≥ 200 家（5w–30w 区间） |
| 风险价值 | 钢贸圈认可的"行业老赖榜"月发布 |

### 2.2 用户角色与权益（再次明确）

| 角色 | 权益 | 义务 | 付费 |
|---|---|---|---|
| 数据贡献者（用 ERP / 对账单 / 合同工具的企业） | 免费基础查询（每月 50 次）+ 风险预警推送 | 自动脱敏贡献本企业应收/付款/履约数据 | 0 |
| 个人付费用户（不贡献数据） | 仅基础免费 | — | 99 元/次 / 999 元包月 / 9999 元包年 |
| 企业版（中大型钢贸） | 全员账号 + API + 风险预警 + 集体维权服务 + 自定义授信策略 | 必须接入数据 | 5w–30w/年 |
| ADMIN（平台运营） | 数据治理、申诉处理、黑名单审核、报告策展 | — | — |

### 2.3 核心流程

#### 2.3.1 数据贡献流程（从 ERP/对账单流入）

```
[贡献方 ERP]
    └─ 应收账款表（脱敏：合同方名+信用代码+金额+账期+逾期天数+付款评分）
        └─ 每日定时同步 → 平台脱敏入库
            └─ 与已有征信主体做实体合并（按"统一社会信用代码"主键）
                └─ 增量更新画像
                    └─ 触发预警引擎
                        └─ 推送给关注该主体的所有用户
```

#### 2.3.2 征信查询流程

```
[查询方]
    └─ 输入企业名 / 信用代码
        └─ 平台 NLP 实体识别 + 联想推荐
            └─ 命中征信主体
                ├─ 基础报告（免费）
                │   - 风险等级 A/B/C/D/E
                │   - 关联合作钢贸数（脱敏）
                │   - 平均账期、最长逾期天数
                │   - 是否在黑名单/灰名单
                └─ 深度报告（付费）
                    - 历史交易明细（脱敏）
                    - 关联关系图谱（接企查查）
                    - 司法/失信/被执行
                    - 风险趋势曲线
                    - 同行评价（匿名）
```

#### 2.3.3 黑名单认证 + 集体维权流程（杀手锏）

```
[贡献方 A]
    └─ 在平台对某主体发起"恶意欠款认证"
        └─ 提交证据（合同/出库单/对账单/起诉书/失信判决）
            └─ ADMIN 审核（24 小时内）
                ├─ 认证通过 → 该主体打"黑标"
                │   ├─ 推送给所有关注该主体的用户
                │   ├─ 进入"老赖榜"候选
                │   └─ 启动集体维权（多方联合诉讼/抵制供货）
                └─ 不通过 → 退回 + 申诉通道

[被认证主体] 可申诉，提交反证 → ADMIN 复核
```

### 2.5 风险评分模型（V1 版，可上线即用）

```
risk_score = w1 * payment_history_score      // 历史付款行为（40%）
           + w2 * overdue_score              // 逾期严重程度（25%）
           + w3 * scale_score                // 经营规模（10%）
           + w4 * legal_score                // 司法/失信信息（15%）
           + w5 * network_score              // 关联风险（10%）

风险等级映射：
  A 优质：80-100
  B 良好：60-79
  C 一般：40-59
  D 高风险：20-39
  E 严重：0-19（含黑名单）
```

模型必须 **可解释**，每个评分维度后跟"扣分原因"，避免被申诉时说不清。

### 2.7 合规与风控（高优先级）

> 这是 4 个产品中合规最敏感的一个，必须严防"未经授权使用个人/企业数据"和"诽谤名誉"。

**数据合规**

- 不采集个人征信数据（避开央行个人征信范畴）；
- 仅采集企业间商业信用数据（B2B），且脱敏存储贡献方身份；
- 数据贡献需用户**明示授权**（在 ERP/对账单工具的服务协议中加专条+二次签署）；
- 提供"**撤回授权 + 数据删除**"通道（按《个保法》《数据安全法》要求）；
- 法务建议申请"**企业征信备案**"（央行下属机构办理）；MVP 阶段定位为"行业风险共享平台"，避免冒用"征信"名称。

**评分公正性**

- 风险评分模型可解释，每个评分项后附"原因"；
- 提供"**异议申诉通道**"，被评分主体可申诉；
- 黑名单认证需要"**多方证据 + ADMIN 审核 + 公示期**"三道闸门，避免误伤；
- 与法律顾问/保险公司绑定，准备好"**名誉权诉讼应对预案**"。

**反欺诈**

- 防止恶意贡献（虚假数据陷害竞争对手）：贡献数据要**多源交叉验证**（合同+出库单+对账单+发票四对一）；
- 异常贡献者（短期大量贡献+主体集中）触发风控；
- 查询行为也要风控：异常高频查询、爬取行为限流。

## 3. 产品 C — 库存资源圈 + 找货撮合（变现层）

### 3.1 业务目标

| 目标 | 指标 |
|---|---|
| 资源密度 | 12 个月内日均在线资源 ≥ 50w 吨 |
| 撮合规模 | 月撮合金额 ≥ 1 亿 |
| 变现 | 撮合佣金 + 担保费 + 金融分润 月毛利 ≥ 100w |
| 与征信联动 | 撮合前 100% 触发征信查询 |

### 3.2 用户角色

| 角色 | 权益 | 计费 |
|---|---|---|
| SELLER | 发布库存（自动从 ERP 同步可控）；接询价；接单 | 免费发布；成交后按佣金 |
| BUYER | 找货；询价；下单 | 免费查找；成交后按佣金 |
| 担保交易方 | 平台中间担保；货款/物流闭环 | 担保费 0.5–1% |
| 物流承运方 | 资源圈撮合后承运；自有/众包 | 平台分佣 5–10% |
| 金融合作方 | 资源圈交易触发的应收账款融资/票据贴现 | 平台分润 0.5–2% |

### 3.3 核心流程

#### 3.3.1 资源发布

```
[SELLER ERP 后台]
    └─ "资源圈"模块
        └─ 选择库存（按规格/仓位筛选）
            └─ 标注"可对外公开" + 设置展示价 / 隐藏价
                └─ 一键同步到资源圈
                    └─ 资源池实时刷新
                        └─ 推送给关注该规格的 BUYER
```

#### 3.3.2 找货 + 询价 + 撮合

```
[BUYER]
    └─ 输入需求："Φ16 三级螺纹 沙钢 8 吨 北京 今日提"
        └─ 智能匹配（综合规格+地点+时效+价格+SELLER 信用评分）
            └─ 列表展示 5–10 家候选
                └─ BUYER 一键群询价
                    └─ SELLER 在小程序接单 + 报价
                        └─ BUYER 选定 1 家 → 触发征信双向查询
                            ├─ SELLER 看 BUYER 风险等级
                            └─ BUYER 看 SELLER 履约评分
                                └─ 合同生成（电子合同 + 在线签）
                                    └─ 选择支付方式
                                        ├─ 直连：BUYER 直付 SELLER（平台仅撮合）
                                        ├─ 担保：BUYER 付平台 → 提货确认 → 平台付 SELLER
                                        └─ 融资：触发金融方介入
                                            └─ 物流派单 → 送货签收 → 闭环
                                                └─ 平台收佣金/担保费/分润
```

### 3.4 数据模型

```
ResourceListing                 // 资源（库存对外发布）
  - id
  - tenant_id (SELLER)
  - sku_id                      // 规格主数据（钢材分类编码 + 规格 + 钢厂）
  - quantity, unit
  - warehouse_id, location_text
  - listing_price               // 展示价（可空）
  - status                      // active/paused/sold_out
  - sync_from_erp               // 是否 ERP 自动同步

InquiryRequest                  // 询价请求（BUYER 发起）
  - id
  - buyer_tenant_id
  - sku_query                   // 规格描述
  - quantity, unit
  - delivery_location, deadline
  - status                      // open/quoted/closed/expired

Quote                           // 报价（SELLER 给 BUYER）
  - id
  - inquiry_id
  - listing_id
  - seller_tenant_id
  - price, freight, tax_included
  - valid_until
  - status                      // pending/accepted/rejected/expired

MatchOrder                      // 撮合订单
  - id
  - quote_id
  - buyer_id, seller_id
  - sku_id, quantity, total_amount
  - payment_mode                // direct/escrow/financing
  - logistics_id
  - credit_check_buyer_score
  - credit_check_seller_score
  - status                      // contracted/paid/shipped/delivered/closed/disputed

EscrowTransaction               // 担保交易
  - id
  - order_id
  - hold_amount
  - hold_at, release_at
  - escrow_fee_rate
  - status                      // holding/released/refunded/disputed

Commission                      // 佣金/分润流水
  - id
  - order_id
  - revenue_type                // commission/escrow/freight_split/finance_split
  - amount
  - settled_at
```

### 3.5 状态机

```
ResourceListing: draft → active → paused → sold_out

InquiryRequest:  open → quoted → closed
                     └─ 24h 无人报价 → expired

MatchOrder:      contracted → paid → shipped → delivered → closed
                            └─ disputed → resolved → closed/refunded

EscrowTransaction: holding → released（货物签收+确认）
                          └─ refunded（异常退款）
                          └─ disputed（争议中）
```

### 3.7 合规与风控

- 平台定位为"信息撮合 + 担保中介"，**不持金融牌照不直接放贷**；

- 与持牌保理/银行合作，由对方做融资主体，平台仅赚信息分润；
- 撮合争议处理 SOP（24h 介入 / 7 日仲裁 / 必要时引入第三方仲裁机构）。

## 4. 跨产品的统一底座（必须先建）

> 三件套不能各自为政，必须共用一套底层平台，否则未来重构成本巨大。

### 4.1 主数据中台

| 主数据 | 说明 |
|---|---|
| **企业主数据** | 统一社会信用代码 / 名称 / 法人 / 注册资本（接企查查） |
| **钢材主数据** | 品种 / 钢厂 / 牌号 / 规格 / 计量单位（理计公式库） |
| **仓库主数据** | 仓库 / 仓位 / 垛位 + GIS |
| **价格指数** | 接钢联/我的钢铁/Mysteel；自有平台撮合价回写 |

### 4.2 用户与权限中台

- 单点登录（钢链通账号）：一个手机号通用三件套；
- 企业-员工组织架构 + 角色权限；
- 企业微信 / 钉钉 / 微信小程序统一登录。

### 4.3 数据贡献与脱敏中间件

- ERP / 对账单 / 合同等多源数据按统一标准入库；
- 脱敏规则可配置（金额脱敏/对手方脱敏/时间窗口模糊化）；
- 提供"贡献日志 + 撤回 + 删除"全套 API。

### 4.4 风控与计费中台

- 统一限流（API 调用/查询次数）；
- 统一计费（按次/包月/包年/分润）；
- 统一对账与发票。

### 4.5 增长分析中台

- 全产品事件埋点（PV/UV/转化/留存/裂变）；
- 增长漏斗看板（运营自服务）；
- A/B 实验框架（病毒位文案/UI 灰度）。
